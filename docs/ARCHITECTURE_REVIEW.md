# 架构评估

日期：2026-11-06。

## 最有价值的部分

- `core/model.py` 已将笔尖、动态、纹理、双重笔刷、颜色动态、湿混色、来源和未知扩展放在公共模型中，适合作为跨格式主存档的基础。
- `core/plugin.py` 的 codec/app 分离让新增格式不必复制整个 GUI 流程；`register_codec` 还统一处理来源指纹和修改后的原生回放边界。
- `core/convert.py` 已采用文件导出优先路线，目标软件不在本机时仍可以生成导入文件，符合纯文件转换方向。
- `.brushpkg` 保存公共模型、资源和来源快照，能避免连续 A→B→C 转换不断丢失信息。

## 需要继续改进的部分

### 按笔刷类别选择映射

公共模型应继续保存完整信息，但映射不能只靠一个“通用默认值”。基础单笔尖、纹理笔、多素材笔、双重笔刷、湿混色和颜色动态需要能力检查和类别化策略。类别策略应加在目标写出器/能力报告边界，避免改变其他类别的默认输出。

### 能力报告要服务决策

当前报告已经有 `warnings` 与 `losses`。后续只增加能影响用户选择的能力项：笔尖数量、纹理、压力/倾斜曲线、湿混色、双重笔刷、目标版本。不要为每个内部字段都增加用户界面开关。

### 诊断与生产代码分开

ABR/BRU 结构检查器应是独立只读脚本，先用于样本差分，不直接把猜测写入生产编解码器。生产修复必须由失败样本和回归测试驱动。

### 必要校验与过度防御的边界

保留文件长度、路径穿越、图片尺寸和压缩量等边界校验；删除没有实际失败案例支撑的多层兜底和自动回滚。转换任务可以单支失败、保留已完成结果，并把原因写进报告。

## 不建议现在重构

不为插件 SDK、机器学习渲染、跨设备同步或所有格式建立统一大抽象。当前最有收益的改动是类别化映射、目标能力说明、ABR/BRU 样本诊断和 GUI 长提示修复。
