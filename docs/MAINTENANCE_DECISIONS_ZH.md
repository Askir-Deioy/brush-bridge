# 长期维护决策

日期：2026-11-06。

这份文件把外部提示词中有价值的内容改写成适合本项目的工作规则。它不是要求每次都执行所有建议；每项工作按用户价值、证据和维护成本决定是否实施。

## 已采纳

### 质量优先，兼容性分层

转换质量优先于“多支持一个文件”。不能为了让一个特殊笔刷通过而降低普通笔刷的输出质量，也不能把高级笔刷静默降成圆笔。按笔刷类别建立转换策略是允许且推荐的，例如：基础单笔尖、纹理笔、多素材/多笔尖、双重笔刷、湿混色和颜色动态分别评估；每类可以有自己的能力检查、映射和验收样本。

### 最小改动，避免无效防御性编程

边界输入要做必要校验，内部流程不堆叠猜测性分支。失败时优先报告清楚的原因，停止当前支路并保留已完成结果；只有存在明确副作用、且回滚路径已经测试时才自动回滚。不会为了“理论上可能的异常”反复重构或撤销已验证功能。

### 先修现有路线，再增加新软件

新增格式必须有样本、维护人力和目标软件验收条件。现有 ABR、SUT、Procreate、SAI2、BRU 等路线的质量问题优先级高于继续扩展格式清单。

### 小众格式独立管理

小众软件按软件/格式分别保存：格式说明、已知样本、版本差异、转换损失和实机记录不混在一张总表里。总兼容性矩阵只做索引，细节回到对应目录。

## 采用但已改写

- “分现代模式和兼容模式”改为按目标软件版本和笔刷类别选择输出策略；只有在存在真实差异样本时才增加模式，不能为了选项数量增加复杂度。
- “实现 ABR/BRU 诊断器”改为先做只读、可复用的结构检查入口；ABR 优先，因为当前用户问题直接涉及 ABR。BRU 诊断器在收集新版/旧版成对样本后再做，避免只为猜测的格式变化写工具。
- “保留所有未知字段”改为主存档保留原始来源和未知扩展，目标格式只写它真正能表达的内容；修改公共参数后禁止错误透传旧原生数据。
- “建立 L1–L5 五层体系”压缩为四层：解析/结构、目标软件导入、重启与参数、真实笔迹。测试报告只使用能帮助决策的层级。

## 暂不采用

- 大规模架构重构、插件 SDK、跨设备同步和机器学习笔迹拟合：当前维护成本高，不能解决眼前的兼容性问题。
- 因为一个软件可能更新格式，就先实现完整版本探测器和多套编码器：先用实际新旧样本确认差异。
- 把“代码能读回”“自己的写入器能再次读回”当成目标软件兼容。
- 把所有诊断字段直接展示给普通用户；高级诊断保留在报告和开发入口，普通流程保持拖入、选择、导出。

## 每次改动的决策问题

1. 这是用户能遇到的真实问题，还是没有样本支持的假设？
2. 这个改动提高哪一类笔刷的质量？会不会降低已有类别？
3. 是否应该给该类别单独的映射，而不是改变公共默认值？
4. 能否用一个最小样本和一个回归测试证明改动有效？
5. 是否需要真实软件或设备才能关闭问题？如果需要，记录为待实机而不是提前关闭。
