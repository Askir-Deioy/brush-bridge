# 已有项目复用审计

这份记录说明哪些现成项目已经检查过、哪些代码可以合法复用，以及为什么当前实现没有把 BrushHub 的目录直接复制进发布包。

| 项目 | 看到的能力 | 许可/再分发条件 | 本项目的处理 |
|---|---|---|---|
| CanderFlower/brush-bridge | 本仓库的格式插件、GUI、打包基础 | MIT | 作为当前底座继续维护 |
| Leon-Schoenbrunn/CSP2PC | CSP `.sut` → Procreate `.brush/.brushset` 的单向参数映射 | MIT | 可以作为后续 Procreate 写出差分测试和映射对照；当前已有自己的双向公共模型和 Procreate 写出器，不复制一套平行实现 |
| tohsakarat/Brush-Converter | ABR、SUT、Procreate 的解包和字段资料 | CC BY-NC 4.0 | 只保留格式知识；如果以后直接移植代码，必须加署名并维持非商业条件，不能混入默认 MIT 发布包 |
| BrushHub 1.0.0 | Procreate 内置素材查找、Procreate → CSP 的模板写出和大量实测记录 | 随包声明程序代码个人使用，再分发前需联系作者；其中还含 CC BY-NC 参考代码和 Procreate 原生素材 | 不复制其程序代码或素材；复用其公开的行为记录和本机可选素材查找思路，发布包继续使用自己的写出器和确定性生成近似 |
| GNOME/GIMP 官方 GBR/GIH 规范与源码 | GBR 的间距/灰度像素头、GIH 的多笔尖管线和维度索引 | GPL 代码；格式规范和行为可参考，代码不能直接混入 MIT 部分 | 继续使用自己的 GBR/GIH 编解码器；把 GIH 的“多笔尖 + 轴/输入索引”作为后续 `tip_order`、压力和速度组合的验证思路 |
| KDE/Krita 官方资源文档 | 预设、笔尖、纹理和 Resource Bundle 的分层组织 | GPL 项目；文档和格式行为可参考，源码不直接复制 | 保持 `.brushpkg` 保存公共模型和资源引用；Krita 输出继续把预设与资源一起验证，缺资源时报告而不是静默替换 |
| 浏览器类转换站 | 多格式读取、预览或商业转换服务 | 未提供可直接合并进本项目的兼容开源许可 | 不抓取网页代码；只把公开的格式兼容结论作为人工验收线索 |

## 复用边界

“已有实现”不等于可以直接拼进来。复用前需要同时满足三个条件：代码许可允许再分发、输入输出方向与我们当前接口一致、资源和参数的语义能在测试中证明。满足条件的代码优先以小模块或明确的适配器接入，并保留原作者说明；不满足条件的项目只作为行为参考或可选的外部工具，不作为 Brush Bridge 的运行依赖。

Procreate 缺少内置形状或颗粒时，程序现在按名称和稳定哈希生成可重复的形状/纹理近似；如果用户已经拥有 BrushHub 或自己的素材库，则优先读取真实图片。这样转换不会因为没有第三方素材库而中止，也不会把第三方素材偷偷变成我们的发布内容。

这轮还从多软件路线发现并修复了一个通用验证问题：MyPaint `.myb` 写出会同时生成 `_prev.png` 预览，逐文件回读时必须只把 `.myb` 交给 MyPaint 解析器。这个修复已加入 `tests/test_versions_and_mypaint.py`，说明“参考别的软件”不只用于格式解析，也用于检查每个格式实际交付的附属资源。
