# 实现与验收记录

## 已实现

- M0：基于上游提交 `b7a886cb857804b898437d30a867bf42469b88ce` 开发，沿用 MIT 许可、现有编解码器和中文界面。
- M1：独立 `.brushpkg` 0.1，公共模型、图片、原生数据、来源快照、哈希检查、未知字段保存、修改后禁止旧原生回放。
- M2：Procreate → 主存档 → CSP/优动漫，保留负向规则和零值；缺关键素材受控失败；转换报告与取消处理。
- M3：五个桌面/平板目标加画世界 Pro、五类目标格式、30 个有向组合的文件回读与基础参数验证。实机状态独立记录。
- M4：桌面界面采用纯文件转换流程，增加主存档格式、优动漫输出、能力说明、数据查看、忽略可选颗粒和取消；启动时不扫描本机软件安装位置。
- 0.5.0 修复：Procreate 原样回写不再因源包缺少内置素材被错误拦截；有公共模型近似时跨格式输出继续进行并记录警告；支持 SAI2 共享包根目录的 `.saitdat` 布局；可复用本机 BrushHub 素材目录。
- 当前回归修复：CSP 生成素材从 RGBA 笔尖保留 alpha 覆盖率；兼容旧 CSP 只设置 `DualUsePatternImage` 的双重笔刷；未知 Procreate 内置形状按名称稳定生成非圆形近似；发布脚本支持 `--force` 覆盖固定目录并只生成一个匹配 ZIP。
- CSP 新笔刷写出会清理修正、速度、模糊、入出笔和喷雾等隐藏模板默认值，避免目标版本读取关闭开关背后的旧参数。
- Procreate 负向压力/速度动态会通过 `Dynamic.response_curves` 保留反向方向，写回 `.brush` 时重新发出负值；避免读取后只剩幅度、方向翻正。
- 逐支转换报告新增 `losses` 结构化字段，与中文 `warnings` 并列记录缺资源、目标不支持、忽略和近似，便于后续兼容性表读取。

构建后的实际启动检查、测试数量和发布文件哈希以发布目录中的验收记录为准，不能由上述实现清单推导。

## 已发现并修正的问题

- SAI2 原生圆笔输出可能丢失非默认间距。非默认间距改用真实笔刷形状保存；20 路线检查曾发现 15%→10%，修复后相应用例通过。
- Procreate 原有解析将 flow/opacity 的零值抬到 0.01，现保留 0。
- Procreate 原有读取会提前简化部分动态。主存档现在同时保留原始参数、负向响应规则和原生归档，导出时解释近似。
- ABR/Procreate 等原生回放可能忽略公共数据修改，增加来源指纹检查。
- Anaconda 基础环境加载 Qt 时发生 DLL 程序入口错误；独立 Python 3.11 的 Qt 导入成功，Windows 开发与打包采用 `.venv-win`。
- 构建器从全局 PATH 收入 Anaconda ICU DLL 会导致冻结程序启动失败。构建进程现使用隔离 PATH，并在没有 Python 环境路径的条件下验证最终可执行文件。
- 冻结命令行环境的默认编码会替换中文，入口现在显式使用 UTF-8，并对中文输出做独立检查。

## 验证边界

`scripts/verify_routes.py` 生成原创控制样本及 20 路线记录。检查数量/名称、尺寸、间距、不透明度、样本笔尖、纹理和压感。尺寸/间距的初始相对误差阈值为 8%，不透明度 5%，压感强度绝对误差 0.08；这些是基础控制样本的回归阈值，不是所有笔刷的视觉还原度标准。

所有路线的 `app_import` 和 `stroke_fidelity` 初始均为 `not_verified`。当前没有执行 PS、CSP、优动漫、SAI2 或 iPad Procreate 的真实导入、重启和绘制验收；不得标为正式实机兼容。原生输出的混色、湿边、复杂曲线、双重笔刷、内置素材引用和软件版本差异需要逐项实测。

Procreate 的原生滑杆编码、间距单位等也需要真实差分样本校准；目前合成源文件使用同一套适配器写出和读取，不能证明对所有原生 Procreate 笔刷的参数解释都正确。原始归档和来源快照已保留，便于后续修正后重新转换。

现有附带测试中，需要外部真实笔刷的测试可能跳过，跳过不代表通过。原创示例及模拟预览不代表原软件的笔迹。用户样本回归另覆盖 Procreate→Procreate、Procreate→CSP、画世界→CSP 和 SAI2 共享包→CSP 的文件级读写。

## 后续实机验收

对可用软件记录产品版本/SAI2 构建日期、源样本哈希、目标文件、导入是否成功、重启后是否保留、大小/间距/压力/旋转是否一致。混色使用有底色与交叠的样例；随机效果检查分布，不要求逐像素相等。Procreate 输出在 iPad 上验证。

画世界 Pro 当前按移动端/平板文件目标接入：读取和生成 `.bru`，复杂参数保留到主存档；没有 Windows 安装位置检测，也没有把实机导入和笔迹核对标成完成。统一绘画引擎、云服务和外观重设计仍在范围外。桌面 GUI 只负责文件导出；目标软件是否安装不参与转换流程。
