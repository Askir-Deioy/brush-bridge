# SAI2 V-HSV 截图差分记录

日期：2026-11-07  
对象：PaintTool SAI Ver.2 Preview.2020.06.17  
目的：从可见色轮和 RGB 数值反推 V-HSV 的可观测映射，不把标准 HSV 直接冒充成 V-HSV。

## 当前证据

用户提供了 11 张 SAI2 色轮截图。截图中包含色相环、二维颜色区域和 R/G/B 数值。可读到的代表性样本如下：

| 样本 | 色相环大致位置 | 方块内位置 | RGB | 当前用途 |
|---|---|---|---|---|
| 1 | 青绿色 | 上边缘靠右 | 008, 255, 186 | 高明度色相样本 |
| 2 | 蓝青色 | 上边缘靠右 | 008, 164, 255 | 高明度色相样本 |
| 3 | 蓝色 | 上边缘靠右 | 008, 038, 255 | 高明度色相样本 |
| 4 | 蓝紫色 | 上边缘靠右 | 142, 008, 255 | 高明度色相样本 |
| 5 | 紫红色 | 上边缘偏左 | 255, 008, 246 | 高明度色相样本 |
| 6 | 红色 | 上边缘靠右 | 255, 008, 078 | 高明度色相样本 |
| 7 | 黄绿色 | 上边缘靠右 | 212, 255, 008 | 高明度色相样本 |
| 8 | 黄绿色 | 上边缘中部 | 212, 255, 090 | 同色相横向梯度 |
| 9 | 黄绿色 | 上边缘偏左 | 212, 255, 175 | 同色相横向梯度 |
| 10 | 绿色 | 上边缘偏左 | 212, 255, 225 | 同色相横向梯度 |
| 11 | 青色 | 上边缘偏左 | 212, 255, 255 | 同色相横向梯度 |

这些样本的共同点是选择点主要落在二维方块的上边缘，纵坐标变化很小。按照标准 HSV，固定 `V=1` 后沿水平方向降低饱和度，正好会出现“一个主色通道接近 255，其他通道逐渐靠近该主色”的结果。现有 RGB 数值与这个趋势一致，不能单独证明 SAI2 使用了普通 HSV，也不能单独证明它使用了 V-HSV。

截图中还可以确认：

- 色相环和二维区域是联动的；改变环位置会改变方块右上角的基准色。
- RGB 显示是 0–255 整数，且截图没有显示额外的透明度通道。
- 当前截图没有覆盖足够的下半区样本，因此无法判断低明度时饱和度是否按普通 HSV 处理。

## 区分 V-HSV 与 HSV 的最小补拍矩阵

保持色相环不动，建议只补拍一个色相（绿色或蓝色即可），在二维区域依次点击以下五个位置：

1. 左上；
2. 右上；
3. 中心；
4. 左下；
5. 右下。

再把同样的五个位置复制到红色和蓝色各一组。每张图保留完整 RGB 数字。这样可以观察：

- 右下是否仍接近“纯色降低明度”；
- 中心和下边缘是否出现比标准 HSV 更高的色彩保留；
- 左下是否接近黑色，还是保留明显色相/饱和度；
- 不同色相在低明度区域是否有一致的压缩或偏移。

如果这些点仍能被标准 HSV 的 `RGB = HSV(h, s, v)` 解释，就不能声称已经复原 V-HSV。只有出现稳定、跨色相重复的偏差，才值得把它抽象成独立 `VHSVModel`，并用误差表驱动实现。

## 第二批截图：低明度样本

第二批截图固定在蓝色附近，补齐了方块的上、中心和下半区。可读到的代表性数值：

| 方块位置 | RGB | 由 RGB 反算出的普通 HSV | 观察 |
|---|---:|---:|---|
| 左上 | 255, 255, 255 | 灰度，V=1 | 白色边界 |
| 左中 | 144, 144, 144 | 灰度，V≈0.565 | 灰度边界 |
| 上中 | 127, 173, 255 | H≈218°, S≈0.50, V=1 | 顶部与普通 HSV 一致 |
| 中部 | 032, 073, 146 | H≈218°, S≈0.78, V≈0.57 | 暗部饱和度明显提高 |
| 左下偏中 | 011, 035, 077 | H≈218°, S≈0.86, V≈0.30 | 暗部仍保留色相和饱和度 |
| 右下偏中 | 000, 000, 075 | H=240°, S=1, V≈0.29 | 非主色通道被压到接近 0 |
| 右侧中上 | 000, 043, 181 | H≈226°, S=1, V≈0.71 | 由蓝色主通道向暗部主色偏移 |
| 右上 | 000, 092, 255 | H≈218°, S=1, V=1 | 顶部基准色 |

这些数据支持一个比“单纯提高 HSV 饱和度”更贴近截图的候选模型。令 `T` 为同一横坐标在方块顶部的归一化 RGB，令 `v` 为纵向明度坐标，则：

```text
RGB(v) = v × T ^ (1 / v)
```

每个通道独立计算，0 通道保持为 0。这个模型可以解释：

- 顶部 `v=1` 时保持原来的 HSV 颜色；
- `000,092,255` 在 `v≈0.71` 时得到约 `000,043,181`；
- 同一颜色在 `v≈0.29` 时得到约 `000,002,075`，截图中显示为 `000,000,075`；
- 中间点 `127,173,255` 在 `v≈0.57` 时得到约 `043,074,146`，与截图的 `032,073,146` 接近，差异主要来自点击位置和整数取整。

这仍然是截图反推的候选模型，不是 SYSTEMAX 公布的官方公式。它已经独立放入 `brush_bridge/core/color_models.py`，并由 GUI 使用；后续如果新的 SAI2 点位否定它，可以替换模型而不重写取色器界面。

## 0.5.7 实机对比反馈

用户将 0.5.7 截图与 SAI2 并排对比。六组 RGB 读数已经基本一致：

| 对照 | Brush Bridge | SAI2 | 结论 |
|---|---|---|---|
| 紫色 | 152, 050, 174 | 152, 050, 174 | RGB 一致 |
| 青绿色 | 058, 227, 198 | 058, 227, 198 | RGB 一致 |
| 蓝色 | 021, 024, 129 | 021, 024, 129 | RGB 一致 |
| 红紫色 | 108, 000, 033 | 108, 000, 033 | RGB 一致 |
| 深紫色 | 047, 000, 082 | 047, 000, 082 | RGB 一致 |
| 黄绿色 | 075, 139, 029 | 075, 139, 029 | RGB 一致 |

对比还发现两个独立的 GUI 问题：

- 原先色环方向与 CSP/SAI 的习惯方向相反；现在改为左上红/橙、右上绿、下方蓝/紫，并同步修正色相指针角度。
- 原先二维方块在每次拖动时用 Python 逐像素重绘，拖动明显卡顿；现在改为 NumPy 向量化生成并按尺寸/色相缓存。400×300 方块连续刷新 30 次的本地测量约 0.16 秒，不再把逐像素循环放在鼠标事件路径中。

RGB/HEX 反算也改成了带量化容差的局部搜索，因此暗部 `000` 通道不会再把 S 坐标错误地固定成 100%。

## 整块截图拟合结论

上一段对话提出的“直接读取整个二维方块，而不是只点几条对角线”的方向是正确的。对角线只能约束部分函数值，整块截图则能检查内部区域是否连续、是否出现局部偏差。

这次六张并排对比图中的 SAI2 方块约为 108×108 像素。按右侧 SAI2 的 H 值裁切内部区域，与当前候选模型逐像素对齐后，得到的中位 RGB 绝对误差约为：

```text
紫色 2.67   青绿色 2.33   蓝色 1.33
红紫色 1.67 深紫色 3.33   黄绿色 2.33
```

均值误差约为 4.7–6.9，主要来自截图中的取色光标、边框抗锯齿和裁切误差。可见区域的视觉渐变已经与 SAI2 很接近，因此现阶段没有必要要求用户把 SAI2 方块强行放大。后续若要进一步压低误差，应补充无光标遮挡的固定色相截图，或使用自动遮罩排除光标区域。

## 当前实现决策

- 不把标准 HSV 冒充成 V-HSV。当前取色器改为使用截图驱动的候选 V-HSV 模型，标准 HSV 只作为顶部边界和误差对照。
- 取色器界面已经改为 CSP/SAI 风格的“外圈色环 + 中央二维方块”嵌套布局；色环方向和指针角度同步校正。
- CSP 前景色同步继续单独调查接口，不与 V-HSV 公式推断混在一起。
- 应用版本已提升到 0.5.8；本次包含模型代码、CSP/SAI 嵌套布局、向量化 GUI 渲染和 RGB/HEX 反算测试，尚未宣称通过 SAI2 实机逐点验收。
